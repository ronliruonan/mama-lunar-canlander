# OPPO 动态锁屏主题（真机试验版）

这是给家人制作的原创锁屏主题试验。目标是在 ColorOS 14 锁屏上用大字显示**当天农历日期**，由主题引擎按日期生成文字。本轮锁屏只做日期，不做节气；现有 Android 桌面卡片不受影响。

2026-10-12：用户报告个人开发者认证已完成；下一步核对主题设计师资质及免费定价／上传能力，见 [NEXT_STEPS.md](NEXT_STEPS.md)。以下设备测试记录仍截至 10 月 9 日。

## 当前状态（2026-10-09）

已用官方 **6.0.0 Mac ARM 编辑器**完成原创桌面主题的必做资源检查并导出 `exports/爸妈农历日期验证_6.theme`。它包含动态锁屏、壁纸和原创图标，`IsGlobalTheme=0`；桌面必做 104/104、锁屏 2/2。此前同一日期布局在实体手机确认显示当天“农历／八月廿九”。

**仍是测试包，尚不能长期交付。** 前一候选包已出现普通试用到期提示；补齐素材不能消除官方试用／授权规则。最新完整资源版正常重启后仍显示正确农历，用户提供了实体截图；截至 17:50 未观察到本次到期提示，自然到期行为、跨午夜、通知遮挡、闰月及长期授权尚未通过。官方支持锁屏单模块预览，但没有查到该预览能永久免费使用的承诺。详细事实、官方依据、包校验与测试矩阵见 [VALIDATION.md](VALIDATION.md)。

## 文件

- `assets/lockscreen-background.png`：深绿、米白、稻穗背景，不含固定日期文字。
- `manifest.xml`：历史对照布局；`NNNN` 是 OPPO 主题引擎格式，官方说明节气当天可能显示节气，因此不作为当前日期专用布局。
- `candidates/lunar-date-only.xml`：当前日期专用布局，使用农历月、日、闰月变量拼接文字。
- `candidates/inputs/`、`tools/prepare_test_assets.py`：可重建的原创输入素材；脚本不能替代官方编辑器导出成品。
- `exports/lockscreen.zip`：从主题编辑器导出的锁屏模块，含多个屏幕比例的布局。
- `exports/mama-lunar-coloros14.theme`：历史 4.5.0 测试包，必做资源不完整，保留作对照。
- `exports/爸妈农历日期测试_6.theme`：4.5.0 日期变量候选，实体手机单日确认过日期，但必做素材登记仍有缺项。
- `exports/爸妈农历日期验证_6.theme`：6.0.0 完整必做资源测试版，最终包由官方编辑器导出。
- `exports/*audit.json`、`evidence/2026-10-09/`：归档检查和编辑器完成清单证据，不等同于平台授权或审核通过。

## 2026-09-28 真机验证

在 OnePlus MT2110（ColorOS 14）上，将 `.theme` 文件放入“下载”目录，经“文件管理”打开后，主题商店识别出“爸妈农历主题”，并可点击“免费试用”。试用后锁屏显示公历 **2026 年 9 月 28 日**和**农历八月十八**，日期与项目应用及香港天文台年历一致，证实这个主题包可以在该设备上动态显示农历日期。主题编辑器的模拟器同一天显示“八月十九”，因此不要用模拟器预览判断农历准确性。

随后主题商店弹出 **“Theme trial has expired. Please end the trial because the resource file is corrupted.”**，提示试用结束并恢复默认资源；已按提示恢复。虽然导出的 ZIP 可正常解压，这个弹窗仍表明主题包或本地试用流程存在兼容性问题，具体原因尚未查明，不能认定包已通过稳定性验证。测试时临时开启的主题商店“所有文件访问权限”已关闭。

初步检查发现，主题包被标记为完整主题（`IsGlobalTheme=1`），但 `icons` 实际是一个空 ZIP，多个其他主题模块也只有占位资源。这可能与资源损坏提示有关，尚未通过重新导出验证，不能据此断定唯一原因。

这次只验证了单日农历显示。**跨北京时间零点自动更新、通知遮挡、重启后显示以及长期安装均未验证。**“免费试用”会到期，尚未找到把自制主题长期应用到该设备的可靠方式。主题编辑器还提示完整主题缺少桌面壁纸、图标、静态锁屏壁纸、设置首页和预览图等必备资源，当前包不满足正式发布检查。请勿将这个测试包当成可长期交付的成品。
